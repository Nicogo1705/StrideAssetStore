# Community Stride Asset Store

[![Browse the store](https://img.shields.io/badge/Community_Stride_Asset_Store-browse-5b8def)](https://nicogo1705.github.io/StrideAssetStore/)
[![NuGet](https://img.shields.io/nuget/v/StrideAssetStore?label=CLI)](https://www.nuget.org/packages/StrideAssetStore)
[![License](https://img.shields.io/badge/license-MIT-green)](LICENSE.md)

A decentralized asset index for the [Stride](https://stride3d.net) game engine, with a storefront,
a desktop app and a command-line tool.

**Nothing is hosted here.** Every asset lives in its author's own public Git repository; this
project indexes them, verifies them, and installs them into your game. There is no server, no
account and no upload: the catalogue is a JSON file generated by CI, and installing is a clone plus
a `<ProjectReference>`.

> ⚠️ **Unofficial** community project. **Not affiliated with, endorsed by, or operated by Stride or
> the .NET Foundation.** It is built so it *could* be adopted by the Stride community later with
> configuration alone — a possibility, not a plan. The registry itself (entries, schemas, CI) lives
> in the companion [AssetContainer](https://github.com/Nicogo1705/AssetContainer) repository.

## Get an asset into your game

Three ways in, same catalogue, same result.

### 1. The command line

```bash
dotnet tool install -g StrideAssetStore
cd path/to/your/game
strideassetstore search grass
strideassetstore add grass
```

`add` finds the nearest `.sln`, `.slnx` or `.csproj` by walking up from the current directory,
clones the asset (and its dependencies) into a shared per-machine cache, verifies its content hash
against the registry, and adds the reference. `list`, `update` and `remove` do the rest.
See the [tool's own README](src/StrideAssetStore.Cli/README.md).

### 2. The desktop app

A local UI with an install wizard, a project manager and a publishing flow. Grab it from the
[releases](https://github.com/Nicogo1705/StrideAssetStore/releases/latest), or let the tool do it:

```bash
strideassetstore app install
strideassetstore app start      # serves http://localhost:5111 and opens your browser
strideassetstore app stop
```

### 3. The storefront in your browser

[nicogo1705.github.io/StrideAssetStore](https://nicogo1705.github.io/StrideAssetStore/) — browse,
search, filter and read asset pages. It can't touch your filesystem, so its Install button hands
over to the desktop app through the `stride-assetstore://` protocol.

### Stride versions

Each asset declares the Stride version it was written against, and the store filters on it. When
your game is on a different build, retarget the asset as you install it:

```bash
strideassetstore add grass --stride 4.4.0-beta5
```

The catalogue currently targets **Stride 4.4.0-beta5**, the newest build published on nuget.org.
Note that 4.4 renamed the asset compiler from `Stride.Core.Assets.CompilerApp` to
**`Stride.AssetCompiler`**; an asset that keeps the old package next to a 4.4 engine still builds
on its own, then breaks every game that references it. Every certified asset is verified to restore
and compile from nuget.org alone, and `asset-e2e` puts one in a real game and runs it.

## Publish an asset

Publishing is a **pull request adding one JSON file** to the registry. You keep your repository,
your license and your release cadence; the store only records where it is and which commit it
trusts. See the registry's
[contributing guide](https://github.com/Nicogo1705/AssetContainer/blob/main/CONTRIBUTING.md) for the
full walkthrough, or use the desktop app's wizard, which does the fork, the manifest and the PR for
you.

To contribute to the tools in this repository instead, see [CONTRIBUTING.md](CONTRIBUTING.md).

## How it works

```
 Author repos (N)              AssetContainer (registry)          StrideAssetStore (this repo)
 ┌────────────────┐    PR      ┌──────────────────────────┐       ┌────────────────────────┐
 │ AssetData/     │ ─────────► │ registry/<id>.json       │       │ Core        (browser)  │
 │  manifest.json │            │ schemas/  catalog/       │ uses  │ Core.Local  (machine)  │
 │  .csproj, imgs │ ◄─clone──  │ CI: validate + build     │ ◄──── │ CLI · Desktop · WASM   │
 └────────────────┘    (CI)    │ index.lock.json (output) │       └────────────────────────┘
                               └──────────────────────────┘
                                          │ raw index.lock.json
                                          ▼
                             Storefront on GitHub Pages ──► you
```

- **Integrity** — the registry pins a resolved git commit plus a deterministic, OS-independent
  SHA-256 of the asset's `AssetData/` folder. The installer re-verifies that hash after cloning, so
  a moved tag or a rewritten history is caught rather than installed.
- **Certification** — a maintainer-approved, immutable commit pin per version. Community assets are
  listed too, clearly marked as such.
- **Validation** — registry entry and manifest against JSON Schema (with `format` assertions),
  category and license against the catalogue, id/file-name consistency, `https://`-only repo URLs.
- **Dependencies** — resolved transitively by id, with cycle and missing detection, auto-derived
  from `<ProjectReference>`.
- **Security** — git runs with no shell, `ext`/`file` transports disabled and option-like arguments
  rejected; clone folder names are sanitised against path traversal.
- **Versions** — an asset can be followed on a branch or pinned to a published tag. Each ref is
  cloned into its own folder of the shared cache, so several versions coexist and "up to date" is
  judged against the ref that clone actually follows.

## Repository layout

| Project | What it is |
|---|---|
| `src/StrideAssetStore.Core` | Pure .NET 10 library with **no filesystem and no git**: models, serialization, catalog loading, search and ranking. This is all a browser needs, so it is all a browser gets. |
| `src/StrideAssetStore.Core.Local` | Everything that requires a real machine: git client, content hashing, `.csproj`/`.sln` inspection and editing, dependency resolution, index building, validation, the installer, and desktop-app lifecycle (download, start, stop). Used by the CLI and the desktop app. |
| `src/StrideAssetStore.Cli` | The `strideassetstore` global tool — see [its README](src/StrideAssetStore.Cli/README.md). |
| `src/StrideAssetStore.UI` | Shared Razor class library: components, pages and services used by both hosts, so the experience is identical online and offline. |
| `src/StrideAssetStore.App` | The **Blazor WebAssembly** storefront deployed to GitHub Pages. |
| `src/StrideAssetStore.Desktop` | The **Blazor Server** desktop app: same UI, plus filesystem and git access. Registers the `stride-assetstore://` protocol on Windows. |
| `tests/StrideAssetStore.Core.Tests` | Catalog, validation and index-building tests, including end-to-end builds against synthetic git workspaces. |
| `tests/StrideAssetStore.Core.Local.Tests` | Installer tests against a synthetic machine: real (tiny) git repos, real `.sln`/`.csproj`, the shared cache redirected into the workspace. No network. |

### The Core / Core.Local boundary

The storefront runs in a browser. It has no business managing git repositories, and it cannot: if
`StrideAssetStore.Core.Local` ever appears in the resolved references of `StrideAssetStore.UI` or
`StrideAssetStore.App` — directly or transitively — **their build fails** with an explanatory error.
The rule is enforced, not documented.

## Working on this repository

```bash
dotnet build
dotnet test

dotnet run --project src/StrideAssetStore.App        # storefront (WASM)
dotnet run --project src/StrideAssetStore.Desktop    # desktop app, http://localhost:5111
```

### Registry maintenance

These commands need a checkout of the `AssetContainer` repository next to this one.

```bash
# Validate every registry entry and manifest
strideassetstore validate --container ../AssetContainer --source git

# Build the aggregated index the apps consume
strideassetstore build-index --container ../AssetContainer --source git --stars

# Cheap refresh: only re-fetch assets whose ref moved (the daily CI job)
strideassetstore build-index --container ../AssetContainer --source git --incremental --stars

# Static per-asset share pages (Open Graph, incl. og:video), sitemap and Atom feed.
# With --app-index each a/<id>/ page IS the SPA shell with meta injected, so the address bar is
# already the shareable URL (Discord and social cards).
strideassetstore generate-pages --index index.lock.json --out publish/wwwroot \
  --site https://nicogo1705.github.io/StrideAssetStore --app-index publish/wwwroot/index.html
```

`--source local` (the default) reads asset checkouts sitting next to `AssetContainer`;
`--source git` clones them.

### Configuration

Both hosts read the same two settings, so pointing the whole thing at another registry is a config
change and not a code change:

- **`Registry`** → `Owner` / `Repo` / `BaseBranch`, defaulting to `Nicogo1705/AssetContainer/main`.
- **`Catalog:IndexUrl`** → where to fetch `index.lock.json`.

### Continuous integration

| Workflow | What it guards |
|---|---|
| `ci.yml` | Build and tests on every push and PR. |
| `release.yml` | On a `v*` tag: **the test suite first** (nothing else gates the publish — `ci.yml` doesn't run on tags), then self-contained desktop builds for Windows, Linux and macOS, each smoke-tested on its native runner (it must serve **and** deliver `blazor.web.js`), checksums, and the CLI published to nuget.org through Trusted Publishing. |
| `deploy-pages.yml` | Deploys the storefront and regenerates the per-asset share pages daily. |
| `asset-e2e.yml` | The promise, end to end, on all three OSes: install the tool, add a published asset to a real Stride game, compile it, and run the game until it renders a frame. |
